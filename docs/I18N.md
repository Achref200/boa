# BOA — three locales

**French (default) · English · Arabic (RTL).** Confirmed by the client.

## Routing

Every public URL carries the locale as its first segment: `/fr/soins`,
`/en/soins`, `/ar/soins`. `src/middleware.ts` negotiates a locale for a bare `/`
from the `Accept-Language` header, falling back to `fr`, and redirects.

Paths themselves stay **French in every locale** — `/en/soins`, not
`/en/skincare`. One information architecture, one set of routes, one redirect
map if BOA ever renames a section. All URLs are built through
`src/lib/routes.ts`; nothing concatenates a path at the call site.

Every page emits `alternates.languages` for the other two locales, and a
canonical for itself.

## Interface strings

```ts
const t = getTranslator(locale);
t('product.addToCart')
```

Messages live in `src/i18n/messages/{fr,en,ar}.ts`. The French file is the
reference: the other two are typed against it, so a missing or misspelled key is
a **compile error**, not a runtime `undefined`.

Interpolation is explicit: `t('product.lowStock', { count: '3' })`.

**The admin application is French.** It is BOA's working language; its labels are
written inline rather than routed through the translator, deliberately and
consistently.

## Content

Content is translated per row, not per file. Every translatable entity has a
`*_translations` table keyed by `(entity_id, locale)` with
`locale ENUM('FR','EN','AR')`. `src/i18n/config.ts` maps the URL segment to the
database enum (`fr → FR`).

A missing translation falls back to the default locale. It never renders a key,
an empty section, or machine-translated filler.

## Right to left

`<html dir>` comes from `LOCALE_META[locale].dir`. Everything else is free,
because the codebase uses **CSS logical properties only**:

- `ms-*` / `me-*`, `ps-*` / `pe-*`, `start-*` / `end-*`
- `inset-inline-start`, `border-inline-end`, `text-start`
- **never** `ml-`, `mr-`, `left-`, `right-`, `text-left`

Icons that encode direction (a chevron in a "next" control) are mirrored with
`rtl:-scale-x-100`. Numbers, prices and times stay LTR inside an RTL line — that
is the browser's bidi algorithm doing its job, and `tabular-nums` keeps columns
aligned.

The Arabic typeface is **IBM Plex Sans Arabic**, self-hosted as a variable font
via `next/font/local`. Arabic is not set in a Latin face with a fallback.

## Formatting

- Money: `formatMoney(value, locale)` — three decimals, TND.
- Dates and times: formatted **on the server** in `Africa/Tunis`
  (`src/lib/tz.ts`, `src/lib/datetime.ts`) and shipped as strings. A slot BOA
  holds at 09:00 must read 09:00 to a customer in Paris as well as in Sousse.
- Numbers in the interface use `tabular-nums` so they do not jitter.

## Adding a string

1. Add the key to `src/i18n/messages/fr.ts`.
2. TypeScript now fails `en.ts` and `ar.ts` — add both. Do not paste the French
   into the Arabic file to silence the compiler.
3. Use it via `t('…')`. Never hardcode.
